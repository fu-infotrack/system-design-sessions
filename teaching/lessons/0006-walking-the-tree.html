Locking · Lesson 6 · ~9 minutes · capstone

Walking the tree

Five lessons, one decision. This is the retrieval practice — no new material, just whether you can use what you have.

The knowledge you already have

Everything so far collapses into a single ordered set of questions. The order is the point: most people enter at step 4 and never ask the first three.

1. Can the data store enforce it?          -> no lock          [L3]
2. Side effect outside the store?          -> idempotency      [L4]
3. Contention structurally avoidable?      -> no lock
4. Blast radius?                           -> picks the family
5. Is the DB the shared state?             -> FOR UPDATE / xact [L2]
6. Efficiency or correctness?              -> lease is / isn't enough [L1]
7. Can the resource reject a stale writer? -> fence, or restructure [L5]

Steps 1, 2 and 3 are the exits — the only branches that leave without a lock. Step 7 has a dead end, and that is deliberate: some designs cannot be made correct with a lock, and the honest output is to change the design.

Keep this

The one-page version is the reference card — print it, or keep the tab. It is designed to be read in the ten seconds before you write a lock.

The practice

Six scenarios, each from a different branch. Take the questions in order rather than jumping to an answer — the discipline is the skill.

Where this goes next
